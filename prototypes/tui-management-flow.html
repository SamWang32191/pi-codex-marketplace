/codex-marketplace — TUI 管理流原型

一句話：Pi TUI 內以 /codex-marketplace 為唯一聚合入口，唯讀發現可走指令或 selector 瀏覽，任何 mutation 強制走 Scope 選擇 → Validation Disclosure → State Revision + Validation Snapshot 綁定的雙重確認（預設 No）→ 原子 commit → 立即 reload → Pending/Applied 回報。本原型用三個結構差異大的變體讓你用點擊感受差異。

本原型要回答的問題（對應 #10）：什麼指令與互動流能在 commit 前讓使用者看懂 Marketplace/Plugin 發現、scope、確認、lifecycle state、不相容、diagnostics 與 reload 後果？
已定決策 Q1–Q4：C /codex-marketplace 聚合 C 混合導航 B 每次顯式 scope B+ C checklist。三變體在下方以 ?variant=A|B|C 切換。
原型假設：Pi ctx.ui.select/confirm/custom 為 TUI 原語；Discovery 走 SelectList；披露走 custom 全螢覆蓋；每步皆顯示 State Revision 與 Validation Snapshot fingerprint，失效即 Rejected as Stale。

Findings 與 Recovery Actions（與 C 的 checklist 同步）

Reload 後果模型（共用說明）

Applied

host-verifiable Bridge re-entry 在預期 State Revision 完成，且無 whole-Plugin Blocking Finding → Completed；有 Warning/Notice 則 Completed with diagnostics

Pending Application

target State Revision 已驗證 commit 但 runtime 未驗證 → 保留 desired state，無自動 rollback，需 Retry Application（同 Revision+Snapshot 才可複用確認，否則重新 preflight）

Blocked / Rejected as Stale

commit 前的 non-waivable target finding → Blocked；State Revision 或 Snapshot 已變 → Rejected as Stale。皆不產生 state mutation
對應 #9 的封閉 Attempt Summary：Completed / Completed with diagnostics / Declined / Blocked / Rejected as Stale / Persistence Failed / Persistence Indeterminate / Pending Application。Persistence Indeterminate 封鎖後續 mutation/application 直至 Repair State。
